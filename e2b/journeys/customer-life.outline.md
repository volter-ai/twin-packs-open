# Runhuman compute over several working days

Actors: the Runhuman operator obtains the E2B team API key and registers two prebuilt images, a RH2 task-agent and the official E2B code-interpreter template built locally. RH2 and the Twenty backend hold that team's key, which grants sandbox lifecycle and list access. Twenty captures each secure sandbox's envd access token and uses it for its filesystem and code requests. The human analyst acts through Twenty. The machine-pool door belongs to the World operator; its fake HTTP replies are explicit verification fixtures, never a claim that a live Python process ran.

1. The operator configures RH2. Its first deployment omitted E2B_API_KEY, so its task cannot start; the operator supplies the issued credential. RH2 allocates a task sandbox, launches its companion host using the actual enveloped Connect request, and releases the sandbox after the ten-minute task. The next morning the operator audits that no machine leaked and checks the template is ready before enabling the E2B driver in Twenty.
2. An analyst opens a CRM analysis conversation. Twenty checks for a tagged session, creates a secure interpreter with a two-minute idle timeout and automatic pause/resume, uploads the two input values, and computes their total. Its Python writes the report whose directory Twenty lists and whose bytes it downloads for the answer. All operations use the captured sandbox id and domain; the local image must provide envd on 49983 and the interpreter on 49999.
3. After three idle minutes the session is paused, preserving memory and files. Twenty locates it by its conversation tag, reconnects and refreshes the exact timeout. Before the follow-up calculation it checks for and removes the previous output directory, recreates an empty one, and reuses the previous Python values. Another idle interval pauses the sandbox; a request for the original input uses enabled automatic traffic resume. The analyst deletes the conversation, and Twenty kills its machine. The next day's abandoned-session sweep finds none.
4. A later RH2 task is allocated with the actual one-hour timeout. Its launcher stalls for 65 minutes, beyond that budget, and the run is abandoned without submitting another Process.Start. RH2 cleanup accepts the one expired-machine not-found response as already gone.

Act-to-door mapping: team/templates and machine pool are World setup doors; allocation/list/kill/connect/timeout are API handlers; the RH2 host is Process.Start; input/output transfers are POST/GET files; output housekeeping is Filesystem.Stat/Remove/MakeDir/ListDir; calculations are the interpreter execute handler. Refusals follow the shown missing credential and expired task, not deliberately malformed traffic.
