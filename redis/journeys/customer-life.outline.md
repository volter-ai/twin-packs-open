# A studio runs its CRM and publishing app on one World-managed Redis

Author: redis-builder

1. The server and worker connections boot with the pinned Redis clients: authenticate when the World definition supplies a password, select their database, register client metadata and names, and read INFO. A stale password is refused. These pinned clients use RESP2 without HELLO.
2. Workspace activation and SDK generation consume storage quota with DECRBY; removing generated bytes restores it with INCRBY. Signing-key verification flushes its buffered counts with INCRBY. The studio signs into Twenty; connect-redis writes, reads, touches and later destroys the session. The CRM cache reads and writes keys and hashes, batches cache writes in MULTI/EXEC and releases locks with EVAL. A malformed queued command discards the transaction; a runtime type error keeps the other writes.
3. Twenty queues a CRM email import, a delayed follow-up, priority work and a periodic scheduler. The pinned BullMQ scripts create job hashes, wait/active lists, completion and delayed sorted sets, locks and events streams; workers pop markers, renew locks, finish or retry work. The admin reads job state and counts, retries a failed job and removes a finished one. Scripts retain preceding writes on error.
4. Live CRM subscriptions publish workspace changes to subscriber connections and unsubscribe when the person closes the page.
5. Scheduler uploads media: upload session and ticket keys expire after an hour, media ids are pushed to a list and read in order. A concurrent start lock is refused by SET NX; a wrong-type lookup errors. The user finishes and removes login state.
6. Cal.com’s API v2 checks the server version for its registered Bull calendar queue, writes, reads and invalidates its calendar cache, and runs its pinned Redis throttling script: the third request is blocked while the initial hit window stays fixed.
7. Connections quit while the retained cache and queued job subjects remain in the World's tree.

The life uses the actual pinned Lua script text and command shapes, never a stand-in job mutation. Unused commands answer Redis's unknown-command error. No account seed or door is needed for a loopback managed Redis.
