# Hugging Face Hub: a cache-transfer diagnostic

Ada maintains localrouter's model-artifact cache. She publishes a small, explicitly synthetic binary transfer fixture in a public model-type repository to reproduce download recovery without shipping model weights. Bob consumes it; neither runs inference.

Actors and grants: Ada's write token belongs to her account and permits creating and pushing her own repository. Bob has his own account and no write grant to Ada's repository. The cache reads public files anonymously. Each credential is captured from the account door; upload and download locations are read from the preceding answers.

1. Ada and Bob make their accounts. Ada creates the public diagnostic repository. An interrupted setup job resumes a day later and retries creation; the conflict includes the existing repository's URL.
2. Ada asks LFS to upload the fixture. Her uploader initially selects a truncated local payload, which is rejected. She selects the complete fixture and retries the returned upload location. A restarted uploader's batch recognizes the already-held object. Ada pushes the manifest, explanatory README and LFS pointer through Git. Bob clones the public repository to learn its revision and files.
3. The cache resolves the manifest at that captured commit, follows its redirect, and reads its content. An interrupted manifest download resumes from byte ten using the saved validator. The binary resolves to a returned CDN URL; the cache reads the uploaded bytes. A worker with a retained partial file resumes its final bytes. A worker whose partial file already holds the complete object gets an unsatisfiable range and can verify and adopt it, as localrouter's cache does.
4. A day later, Bob notices a typo in a copied repository name and corrects it before resolving main and following the returned manifest location. He checks the Hub’s repository information for the corrected name, confirming its author, public visibility and published commit, then checks the original copied typo and receives the single missing-repository refusal. The public diagnostic remains available to the model team; the transfer problem is reproduced without calling inference.

Doors and operations: account acts use `/_twin/users` (`users`); repository creation uses `post_api_repos_create`; publication and clone use the manifest's Git/LFS content screens; manifest and binary downloads use `get_namespace_repo_resolve_rev_path`, `get_api_resolve_cache_models_namespace_repo_rev_path` and the CDN content screen. The platform’s read-back scope uses `get_api_models_repo_id`; Bob’s final metadata checks exercise its successful and missing-repository answers. The story reaches the demanded pinned download and resume behavior. Other malformed requests and options belong in separately cited unreachable records, not invented customer acts.
